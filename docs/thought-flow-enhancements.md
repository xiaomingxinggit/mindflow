# 自由连接、实时 Markdown 与连线数据流

2026-10-23。状态：功能、代表性浏览器验收、最终构建与静态检查已完成。
下文保留确认的需求与实施依据，实际实现、限制和已执行结果见末尾记录。
执行聊天：[DEV](codex://threads/01a16858-7e99-7653-a8cb-63b51297a1f1)。
实现基线：`5e8b6aa`，已有现代 / 系统风格及系统字体。

## 目标与范围

让用户在无限画布上边想边写，容易把想法连起来，并直接阅读完整内容。
本轮交付下列三项，继续使用现有本地单白板和 Excalidraw 编辑核心。

| 范围 | 已确认的结果 |
| --- | --- |
| 快速连接 | 节点提供连接点；拖向已有节点吸附连接，拖向空白创建节点并连接，立即输入内容；顶部 5 号箭头采用相同规则 |
| Markdown | 节点、便签、独立文字、连线标签全部支持；包含表格、图片、数学公式；原位编辑并实时渲染 |
| 内容尺寸 | 默认完整展开、自动增高，允许手动调整宽度；连线标签也遵循此规则 |
| 数据流动效 | 沿连线一直循环流动；每条连线单独开关及调速；新连线默认静态 |

现代风格仍为默认，系统风格保留，两种风格使用系统字体。此轮不重新设计整套界面。
数据流指关系的可视化动画；本轮没有节点计算、数据执行引擎、运行按钮或流程调度需求。

## 一、连接与拖线创建

### 用户操作

1. 鼠标悬停或单选一个可连接节点时，在上、下、左、右显示连接点；平时隐藏。
   节点范围包括矩形、菱形、椭圆和便签，不给文字、图片、画笔或画框强加节点语义。
2. 从连接点拖动显示预览线；靠近另一节点时目标高亮，释放后绑定两端。
   吸附范围按屏幕距离设置，缩放后仍容易连接，无需精确瞄准边缘。
3. 从已有节点拖到空白处释放，创建一个使用当前风格的默认节点，并连接源节点。
   新节点立即获得文字编辑焦点，可以直接开始输入，不必再次双击。
4. 使用顶部第 5 项箭头工具（含对应快捷键）从已有节点起笔时，采用相同规则。
   从空白起笔时保留自由画箭头的行为，不在空白起点自动补造节点。
5. `Escape` 取消拖动不产生半成品，短点击连接点不创建节点；
   普通移动、框选、平移和编辑文字继续正常工作。

### 连接与历史

- 箭头绑定原生节点 ID；移动或调整节点后连接继续跟随，不用一条视觉线模拟绑定。
  文字命中应映射回其节点容器，命中和连接点位置考虑旋转、缩放及元素层级。
- 自动创建的节点和连线作为一次可撤销操作；初次输入的历史应与创建体验一致，
  避免撤销留下孤立线或空壳。继续修改已有文字使用正常编辑历史。
- 快速连接与 5 号箭头共用连接判定和创建逻辑，避免两套手势产生不同结果或重复元素。
- 新节点沿用当前画布风格，使用系统字体；新连线默认不启用数据流动效。

## 二、所有文字实时渲染 Markdown

### 支持内容

节点、便签、独立文字、连线标签使用同一套能力，既支持新内容，也能编辑已有文字。
不将连线标签缩减成只支持单行或基本行内格式。

| 内容 | 要求 |
| --- | --- |
| 常用 Markdown | 标题、段落、粗体、斜体、删除线、链接、引用、分隔线 |
| 列表 | 有序 / 无序列表、嵌套列表、任务列表；任务勾选能保存 |
| 代码 | 行内代码、围栏代码块，使用系统等宽字体 |
| 表格 | 表头、行列、对齐；可在编辑状态直接修改单元格 |
| 图片 | Markdown 图片引用；粘贴 / 上传图片可插入到正在编辑的内容，可修改引用与显示尺寸 |
| 公式 | `$…$` 行内公式、`$$…$$` 独立公式；输入时同步预览，可重新编辑公式源文 |

### 编辑体验

- 双击原位置进入编辑，输入时即时呈现格式；当前编辑位置显示必要的 Markdown 语法。
  表格直接编辑单元格，公式可显示源文及即时结果，不采用左右分栏的独立编辑页面。
- 普通文字使用系统无衬线字体，代码使用系统等宽字体；保留既有字号与颜色控制。
- `Enter` 换行，`Ctrl / Cmd + Enter` 或点击外部完成编辑。中文输入法组词时不触发完成。
  编辑期间文字快捷键优先，不能误触画布删除、创建图形、平移或全选画布。
- 只为当前文字挂载可编辑实例；其他元素展示渲染结果，保持画布选择和拖动可用。
- 保留唯一可恢复的 Markdown 原文；格式化显示不能覆盖、丢失原始内容。
  使用成熟的编辑 / 解析能力处理嵌套结构，不自行用正则拼装完整 Markdown 编辑器。

### 尺寸与位置

- 内容默认完整展开，不用固定高度的内部滚动区或省略号隐藏内容；宽度可手动调整，
  文字换行并自动计算高度，图片按内容宽度等比适配。
- 形状内文字增长时，外层节点同步容纳内容；保持文字与节点绑定，连线随节点尺寸更新。
  菱形、椭圆按实际可用文字区域排版，不能把表格和图片裁出节点。
- 独立文字及连线标签同样支持调宽、自动增高。标签区域独立调整宽度，
  不通过拉长箭头来模拟文字宽度；拖动节点后标签继续跟随连线。
- 平移、缩放、旋转、选择、多选、复制和图层顺序应与原生场景一致。
  图形与 Markdown 不能各自在不同坐标系漂移，浮层不能常驻遮挡画布命中。

## 三、每条连线独立的数据流动画

- 新建及无动效记录的已有连线默认静态。选中连线后显示「流动效果」开关和速度滑杆。
- 开启后使用小圆点沿实际连线路径循环移动，颜色跟随线色；箭头和底线保留。
  标准速度为默认，滑杆连续调整慢到快，不增加播放 / 暂停整张流程的操作。
- 流向跟随箭头指向；未额外指定方向的普通连线沿起点到终点移动。
  双向箭头可采用双向流动，开发时将实际规则写入使用说明。
- 拖动节点、改折点、缩放或平移时，动画跟随真实路径，包括现有折线与圆角部分。
  文字标签置于动效上层，避免圆点穿过表格、公式和图片影响阅读。
- 每条连线的开关和速度随文档保存、复制、导入导出，并能撤销 / 重做。
  切换现代 / 系统风格保留这些设置，原有手动线色控制继续可用。
- 动画进度属于瞬时显示状态，不逐帧更新元素、撤销历史或 IndexedDB；
  没有启用动效的线不运行独立动画，后台页面可停绘。无需建立通用动画引擎。
- PNG、剪贴板图片和普通 SVG 导出保留清晰静态连线；本轮不新增视频或动图导出。
  可编辑画布文件保留动效配置，重新打开后按配置继续循环。

## 四、结合当前项目实施

### 保留的基础

- 当前为 React 19 + TypeScript + Vite，锁定 `@excalidraw/excalidraw@0.18.1`。
  原生核心继续负责场景元素、ID、绑定、选择、变换和历史；不退回 React Flow 或重做整个白板。
- `src/Whiteboard.tsx` 承接编辑器与工作区入口；复杂的新功能拆成少量组件 / 工具函数，
  不把整套逻辑继续堆进一个组件，也不增加插件框架、通用仓储或第二套业务历史。
- `src/visualStyles.ts` 的风格切换和 `src/systemFont.ts` 的系统字体行为保留。
  新增元数据必须与已有 `mindflowStyle`、`mindflowNote` 及其他 `customData` 合并。
- `src/whiteboardStorage.ts` 仍负责本地场景和图片，沿用初始化完成后保存、500ms 防抖、
  顺序写入与可见错误提示。旧 localStorage 不覆盖，旧文件转换入口保留。

### 首先验证的集成点

连接交互也有两个已核实的接口边界：原生 `onPointerDown` 回调发出时，箭头创建 / 手势注册
可能已经发生，不能将它当作可取消的前置事件；公开 API 没有开始文字编辑或历史事务的接口。
快速连接优先在容器捕获阶段识别节点起笔，将四边点与箭头工具交给同一小型手势状态处理，
空白起笔放行原生交互。预览和新节点首次编辑可暂存在轻量展示层，确认后将节点、文字、
箭头及绑定一次提交到原生场景，以保证一步撤销；不要事后补元素后再清空历史来伪造事务。
绑定需同时维护箭头端点和节点 `boundElements`；仅合入必要变化，保留原 ID、其他绑定与
已删除元素的历史状态，不重建整幅场景。首次编辑确认前的临时预览不写入持久化。

已核对本地 0.18.1：原生 text 是纯文本，canvas / SVG 按纯文本绘制，原位编辑使用 textarea；
`ExcalidrawProps` 没有替换文字渲染器或文字编辑器的接口。
`renderEmbeddable` 不能替代完整文字渲染 / 导出，不能将完整 Markdown 当作原生已具备的能力。
DEV 开始后先打通一个包含表格、图片和公式的文字对象：
原位实时编辑 → 调宽和增高 → 原生选择 / 拖动 → 撤销重做 → 保存恢复 → PNG / SVG 导出。
这是实施顺序中的可用切片，验收范围仍包含全部四类文字。

优先使用公开 API 与轻量的富文本展示 / 编辑层。若采用 DOM / SVG 展示层，必须同时处理
原生纯文本的重复显示、命中范围、层级、图形变换与导出，不可只覆盖一层网页预览。
公开 API 的缺口应先在本地安装包中核实；必要时采用小范围、可复现的版本适配，
记录位置及原因，不手改 `node_modules` 或静默重写整个编辑器。

- Markdown 原文、人工指定宽度与动效参数必须进入场景持久化和原生历史可观察的数据中；
  渲染缓存、编辑器实例、动画进度不进入文档。明确唯一原文来源，避免多个副本互相覆盖。
  优先复用 `originalText` 保留原文，扩展信息进入合并后的 `customData`；
  如实现需要不同方案，记录唯一来源及原生文本后备如何生成。
- 新元数据优先放在对应元素命名明确的 `customData` 字段，并保留所有未知字段。
  所有结构变更采用原生版本与历史更新机制；风格重测不能将 Markdown 当纯文本重新挤压。
- 原生导出不会自动包含外部渲染层。文件菜单、命令面板和导出快捷入口需使用一致的导出链路，
  PNG / SVG / 剪贴板图片真实包含渲染内容，保持位置、尺寸和系统字体。
- 本地插入图片需要随工作区和备份文件保存，不能只记录会失效的临时 blob URL。
  本地已核实原生 `serializeAsJSON(..., 'local')` 只保留原生元素 `fileId` 引用的文件，
  仅在 Markdown 元数据中引用的图片会丢失；必须在同一文档序列化链路中补齐资源收集。
  外链图片加载失败显示简单占位及可修改地址；正常本地图片的离线恢复与导出需要实际验证。
- `.excalidraw` 保存 / 打开须往返保留原文、资源、宽度及动效设置。保留可读文本后备内容，
  不承诺上游 Excalidraw 能播放本项目动效或提供相同富文本编辑体验。
- 链接、图片及公式按所选成熟库的标准方式处理；不执行导入文字中的脚本，
  无需增加与本地个人白板无关的权限体系或层层兜底。
- 输入预览、原文、真实元素边界与容器变化要按一次编辑组织历史。
  不可每次按键都用 `NEVER` 推进原生 snapshot，导致最终提交无法撤销；
  也不可通过动画或排版回调持续制造历史条目。

## 五、实施顺序与版本控制

1. 在方案所在功能分支开始，确认工作区状态；保护外部未跟踪的 `AGENTS.md`。
2. 完成上述 Markdown 可用切片，确定原文、布局、历史、图片和导出的最小一致模型。
   继而覆盖全部四种文字入口、已有内容和风格切换。
3. 完成四边连接点、目标吸附、拖空白建节点和 5 号箭头的一致手势；
   自动创建直接进入同一个 Markdown 编辑器。
4. 添加连线开关 / 速度属性及循环流动展示，复用既有场景路径和持久化模型。
5. 同步 README 的实际可用功能、快捷键与备份说明，补充本文的真实验收记录。
   新依赖同步 lockfile，保留开源许可；不要提前将未完成目标写为已实现。
6. 可以按完整可用的功能切片做聚焦本地提交；最终检查通过后提交剩余变更。
   不主动推送或创建 PR，不把截图、日志、生成文件或外部 `AGENTS.md` 顺带提交。

不因实现存在适配工作就缩减用户已经确认的 Markdown 范围。若遇到确切的能力阻塞，
说明已核实的原因、已完成部分和可行取舍；一般实现选择由 DEV 自主处理，不反复索要确认。

## 六、适量验收与交付

完成后运行 `npm run build`、`npm run lint`、`git diff --check`。
浏览器以一份代表性画布串起以下流程，不为本轮新增大规模测试框架或反复穷举原生功能：

1. 从连接点连接已有节点，再拖空白创建节点并直接输入中文；用 5 号箭头重复一次，
   检查从空白起笔的自由箭头、取消、拖动后的绑定及一次撤销 / 重做。
2. 四类文字都能实时编辑 Markdown。用一份综合内容覆盖表格、图片、两类公式、列表和代码；
   连线标签至少验证富内容、调宽和完整增高；检查中文输入法、快捷键隔离和再次编辑原文。
3. 两条线分别保持静态 / 开启动效，调整其中一条速度；移动节点和改线路径，
   检查标签可读、独立设置及撤销重做；确认动效不让保存状态不停跳动。
4. 在同一画布切换现代 / 系统风格，确认 Markdown、节点绑定和动效配置保留；
   多选复制一次，刷新恢复一次，画布备份文件往返一次。
5. 实际导出 PNG、SVG 和剪贴板图片，检查表格、图片、公式与普通图形都存在；
   导出的连线是清晰静态图。检查 1280×800 / 1366×768 布局并保留代表性截图。

只在发现实际问题或代码再次修改时追加相关验证；不做无关压力测试、浏览器矩阵或过度防御性代码。
DEV 最终说明实现内容、实际通过的检查、分支 / commit、截图、本地预览地址及明确剩余限制。

## 实施与验收记录

### 实现分工与数据

仍由 Excalidraw 负责真实元素、选择、移动、绑定和历史，没有第二套文档历史。

| 模块 | 当前职责 |
| --- | --- |
| `QuickConnections.tsx` | 四边连接点、24px 屏幕距离吸附、5 号箭头共用手势及新节点草稿 |
| `useRichText.tsx` / `RichTextEditor.tsx` | 一次只挂载一个 Milkdown Crepe 7.22.3 原位编辑器；完成编辑后整步提交 |
| `richTextModel.ts` | 原文、宽度、完整高度和容器尺寸；按需要更新原生绑定 |
| `markdownRendering.ts` | markdown-it / KaTeX 渲染、DOMPurify 清理、图片资源解析、完整尺寸测量及位图缓存 |
| `richTextBridge.ts` / `scripts/excalidraw-rich-text.ts` | 0.18.1 原生绘制、编辑入口、绑定更新、导出和资源序列化的可复现适配 |
| `FlowAnimation.tsx` / `flowAnimationGeometry.ts` | 独立连线配置；从原生 SVG 实际笔画取样，在 Canvas 展示层绘制圆点 |

| 数据位置 | 内容 |
| --- | --- |
| `text.originalText` | 唯一可恢复的 Markdown 原文；`text` 保留可读后备内容 |
| `text.customData.mindflowMarkdown.width` | 用户指定的内容宽度 |
| `text.customData.mindflowMarkdown.imageFiles` | 该原文引用的本地图片资源 ID |
| `line.customData.mindflowFlow` | `{ enabled, speed }`，默认关闭、速度默认 70 |
| 原生 `files` | 本地图片 data URL，以 `mindflow-file:<id>` 从 Markdown 引用 |
| 内存缓存 | 内容位图、编辑器实例、路径取样和动画进度；不写入文档 |

新元数据与 `mindflowStyle`、`mindflowNote` 及未知 `customData` 合并。
图片上传与粘贴共用持久资源入口，原生本地文件序列化补齐只被 Markdown 引用的资源，
不依赖临时 blob URL。表格直接编辑单元格，任务在编辑状态勾选；公式使用 Crepe 默认的
LaTeX 能力提供源文和预览。Enter 换行，Ctrl / Cmd + Enter 或外点完成，Escape 取消。

从连接点拖空白时，新节点、文字和箭头暂存在草稿展示层；确认输入后一次提交，取消或空内容
不插入场景。已有目标连接直接提交一条绑定箭头。原生文字快捷入口也通过适配进入同一编辑器。

### 适配与限制

- Vite 读取官方 0.18.1 的可读 ESM，按固定源码锚点加入小范围适配，生产仍经 Vite 构建压缩。
  适配器验证包版本与锚点，未手改 `node_modules`；升级包时需重新核对。
- Markdown 渲染结果参与原生元素的 Canvas / SVG 绘制，元素仍由原生编辑器命中、选择和移动。
  真实文字宽高写入原生场景，容器按内容增高，节点关联连线使用原生绑定计算更新。
- PNG、SVG 与剪贴板图片共用富内容渲染链路，导出保留静态连线。
  SVG 的 Markdown 区域是嵌入位图，普通图形仍为矢量；不承诺富内容是可编辑的矢量文字。
  可编辑原文、宽度、资源及动效以 `.excalidraw` 备份保存，不承诺上游编辑器有相同富编辑或播放能力。
- 外链图片依赖地址可访问及浏览器跨域读取条件；加载失败呈现占位，可编辑地址。
  本地图片通过文档资源保存，能够随备份离线恢复。
- 流动速度范围为 20–180 个画布单位 / 秒，默认 70。普通线及终点箭头从起点到终点，
  只有起点箭头时反向，双端箭头双向。滑杆拖动只预览，释放后一次写入原生历史。
  动画逐帧只读场景并绘展示层，没有开启的线不运行，后台页面停绘；文字边界遮挡圆点。

### 拖动性能修复（2026-10-23）

针对节点拖动掉帧，以 `0de4b6c` 为基线，在独立浏览器测试配置中使用同一份代表性画布：
12 个元素、6 个富文字、2 条箭头（1 条开启动效）及 1 个 Markdown 本地图片资源。
视口为 1366×768，执行 120 次相同圆弧往返 `mouse.move`，用 CDP 以 0.5ms 间隔采样 CPU，
同时记录任务、脚本耗时及动画帧间隔，并分别对照 Vite 开发模式与生产预览。

实际主要热点是 React JSX 创建及原生菜单重复渲染：每次位置更新都会重新创建传给
Excalidraw 的 children，使其 memo 比较失效。`Whiteboard.tsx` 现在用 `useMemo` 保持原生
编辑器子树稳定，并固定新建画布回调；连接点等展示层继续随每次位置更新。
`markdownRendering.ts` 同时在生成渲染 key 前比较原文、宽度、字号、颜色与引用图片数据，
避免未变化的富文字反复解析 Markdown 和序列化图片。原文变化会重新解析资源 ID，
同 ID 图片替换也会使缓存失效。本次未修改动效路径或自动保存调度。

| 模式 | 脚本耗时（修复前 → 后，ms） | 主线程任务耗时（ms） | 帧间隔 P95（ms） | 超过 25ms 的帧间隔数 |
| --- | --- | --- | --- | --- |
| 开发模式 | 1437.882 → 421.766 | 1898.265 → 670.051 | 20.8 → 7.0 | 5 → 1 |
| 生产预览 | 369.822 → 218.098 | 654.648 → 498.940 | 7.1 → 7.0 | 1 → 1 |

以上是该次输入序列的累计耗时。输入没有固定节拍，不能把执行时长或帧间隔换算为持续 FPS
基准；生产预览的最大帧间隔仍为 76.4 → 83.3ms，没有改善，因此不声称消除了所有长帧。
开发模式额外开销更明显，生产对照也确认了应用自身重复工作的减少。
