# 节点文字居中失效修复方案

2026-10-24。状态：已完成源码调查及浏览器复现，尚未实施修复。
执行聊天：[DEV](codex://threads/01a16858-7e99-7653-a8cb-63b51297a1f1)。
调查时 HEAD 为 `4110f14`，工作区包含其他未提交改动；以下依据当时实际工作区源码。

## 问题与预期

用户截图中，浅紫色圆角矩形内的“你好”靠近左侧，未按默认值水平居中。
这里按截图中的形状绑定文字处理；Markdown 表格中的单元格继续遵守自己的列对齐语义。

普通节点的新文字应默认水平居中、垂直居中。编辑中、完成后、再次编辑、刷新和导出时
应保持一致；用户选择左／中／右及上／中／下后，显示应真实反映元素属性。
便签沿用已有左上对齐及 16px 内边距，独立文字保留自己的对齐属性。

截图能证明水平偏左，不能单凭截图认定垂直居中也失效。

## 已确认的原因

| 层次 | 源码位置 | 当前行为与影响 |
| --- | --- | --- |
| 元素数据 | `src/richTextModel.ts` 的 `createTextDraft` | 普通绑定文字已经写入 `textAlign: 'center'`、`verticalAlign: 'middle'`，默认值本身正确 |
| 共用样式 | `src/MarkdownContent.css` 第一条规则 | 展示与编辑内容根节点都被固定为 `text-align: left` |
| 显示位图 | `src/markdownRendering.ts` 的 `createMeasureHost` | 只设置宽度、字号、颜色，没有把 `text.textAlign` 传入 HTML 宿主 |
| 画布桥接 | `src/richTextBridge.ts` 的 `drawCanvas`、`createSvg` | 绘制的是整张富内容位图，原生文字对齐无法改变位图内部的排版 |
| 缓存 | `src/markdownRendering.ts` 的 `renderInputs`、`renderKey` | 输入比较和缓存 key 都遗漏 `textAlign`，切换属性后仍可能复用旧位图 |
| 编辑入口 | `src/RichTextEditor.tsx` 的 `Props` 及 `src/useRichText.tsx` 的编辑器调用 | 未传对齐属性，编辑状态仍固定左排 |

因此，当前居中的是一个几乎铺满节点宽度的文本框，框里的短句仍从左边开始。
这与截图现象一致，是本项目富文本适配的缺陷。

另一个已由源码确认的相关问题：`richGeometry` 对普通形状的文本框位置一律按居中计算，
没有读取 `textAlign` 和 `verticalAlign`。原生 `computeBoundTextPosition` 则会读取这两个属性。
编辑预览、提交与原生拖动／属性修改之间存在布局规则分歧；本次应一并收敛，避免用户切换
垂直对齐后，重新编辑又跳回中间。该问题的具体交互表现仍需 DEV 复现验收。

## 已执行的浏览器复现

使用独立 Playwright 会话 `alignment-plan`，打开 `http://127.0.0.1:5173/`，
视口为 1280×800，画布缩放 100%；没有操作用户现有浏览器会话。

1. 用矩形工具从屏幕 `(440,260)` 拖到 `(650,420)`，创建 210×160 的普通节点。
2. 双击节点中心，输入“你好”。
3. 读取 `.ProseMirror`：计算样式 `text-align` 为 `left`，文本框为 178×27，
   左上角 `(456,326.5)`，文字显示靠左。
4. 按 Ctrl+Enter 完成，点击空白。读取场景：文字仍为 `center / middle`，
   文本框中心 `(545,340)` 与形状中心完全一致，但可见字形靠左。截图已目视确认。
5. 选中节点，点击原生“右对齐”，场景属性变为 `right`；显式再次调用
   `prepareMarkdownRender`，仍返回同一缓存对象，revision 保持 `1`。

复现中的位图缓存 key：

```json
["你好\n",178,18,"#343044",[]]
```

对齐由 `center` 改为 `right` 后，此 key 不变，证实缓存失效条件缺失。
临时截图在已忽略的 `output/playwright/alignment-plan-edit.png` 和
`output/playwright/alignment-plan-view.png`，不提交产物。

## 修复设计

### 1. 使用同一份对齐数据

以 Excalidraw 元素的 `textAlign`、`verticalAlign` 为唯一依据，保留现有存储格式。
普通节点继续使用 `center / middle` 默认值，便签继续使用现有左上规则。
已有元素的显式对齐值原样保留，无需迁移或批量重写全部文字。

### 2. 让显示与编辑读取水平对齐

- `createMeasureHost` 把 `text.textAlign` 传入内容宿主；同步测量和最终位图走同一规则。
- `RichTextEditor` 增加与原生元素一致的对齐类型，由 `useRichText` 传入当前元素值。
- 共用 CSS 移除强制左排，改用局部 CSS 变量或继承，缺省仍为左排。
  必须让实际 `.ProseMirror.mindflow-markdown-content` 根节点读到对齐值；仅给外层
  wrapper 设置 `textAlign` 会被现有内容根节点规则覆盖。
- 对齐应用于节点普通段落、标题等内容；代码块及列表保留适合阅读的内部布局，
  Markdown 表格保留显式列对齐。图片、公式、表格等块内容保持既有布局并做回归，
  避免通过通配选择器把每个内部元素都设成居中。

### 3. 补全缓存失效与更新触发

- 把 `textAlign` 加入 `renderInputs`、快速比较和 `renderKey`；位置变化仍不重新生成位图。
- 对齐改变时生成新位图、推进缓存 revision，并通过既有 redraw 刷新画布。
- 检查原生属性切换、撤销和重做的触发链。`Whiteboard` 已维护 `scene.revision`，
  但 `useRichText` 的渲染 effect 当前只依赖 `elements / files`，未消费该版本。
  需要验证原生复用数组时的更新，必要时接入已有版本或富文字输入签名，不能只改 key
  却没有再次执行渲染。继续保留输入快速比较，避免拖动节点时反复解析或生成整图位图。
- 继续使用 `wantedKeys` 防止旧异步结果覆盖新对齐结果，验收快速连续切换对齐的最终状态。
- `verticalAlign` 只改变文本框位置时，无需加入位图 key；需要更新相应几何。

### 4. 收敛文本框定位规则

- 核对 `richGeometry` 与原生绑定定位在矩形、菱形、椭圆上的规则，统一编辑预览、提交、
  拖动、缩放与属性切换所使用的内容区域及对齐算法。
- 优先复用已存在的原生定位能力；如需暴露桥接方法，保持适配器的固定版本与锚点检查。
  水平位图修复本身不要求修改原生渲染补丁，避免扩大依赖改动。
- 区分文本框在容器内的位置与框内各行的水平对齐，不能仅把文本框再次移动到中心。
- 保留内容自动增高、手动调宽、便签 16px 内边距、箭头标签原生位置与旋转／连接绑定。
- 布局修改仍在原生事务中完成；不另建业务历史，不因展示刷新增加持久化写入。
