# 多选元素居中成列与自定义间距方案

状态：待 DEV 实施和验收。本文记录需求和建议实现，不代表功能已经可用。
日期：2026-10-24。

## 需求与效果

用户框选多个散落的对象后，点击左侧「对齐」第一排第二个居中按钮，希望对象沿同一条竖直中心线排成一列，相邻对象互不重叠，并能自行调整间距。

用户截图 1、2 是操作前的五个圆角矩形；截图 3 是不符合要求的原生结果：左右中心虽然对齐，原先纵向有交叠的对象仍互相压住。

本次必做的是「左右居中 + 纵向成列 + 指定边缘间距」三个步骤合成一次操作。点击截图中的原按钮即得到结果，无需再手动逐个拖开。

以下默认间距、排序及位置锚定规则是本方案的建议默认值，用户未逐项指定。水平成排可在后续按同样规则扩展，本次不作为交付前提。

## 已核实的现状

- 当前依赖固定为 `@excalidraw/excalidraw@0.18.1`。
- 截图按钮对应 `actionAlignHorizontallyCentered`，动作名为 `alignHorizontallyCentered`，原生参数是 `axis: 'x', position: 'center'`。不要误改 `alignVerticallyCentered`；后者统一的是 Y 中心。
- 安装包 `dist/dev/index.js` 中的 `alignElements` 使用 `getMaximumGroups` 识别组合，平移后调用 `updateBoundElements`。它只改指定轴，所以保持原 Y 时可能出现截图 3 的重叠。
- 安装版 `ExcalidrawImperativeAPI` 提供 `registerAction`；`ActionManager.registerAction` 按动作名更新注册表。属性面板的 `renderAction('alignHorizontallyCentered')` 从该表获取执行函数与 `PanelComponent`，可优先通过同名动作接入。
- `src/Whiteboard.tsx` 已持有原生 API、选区和场景；位置变化经现有 `onChange` 进入保存链路。
- `src/richTextBridge.ts` 的 `rebindRichContainers` 及 `scripts/excalidraw-rich-text.ts` 中的原生路由桥可作为连线更新的参考。不能假设单独修改 `x/y` 后调用 `updateScene` 就能处理所有绑定。

## 交互规则

1. 保留截图中按钮的位置和居中图标，将其提示与可访问名称说明为「居中成列」。点击后直接使用当前间距排列当前选区。
2. 在原「对齐」区域下方增加紧凑的「排列间距」数值输入与「应用」按钮，说明文字为「相邻对象边缘之间的距离」。布局不能挤乱原有对齐图标。
3. 建议默认间距为 `24` 个画布单位，界面可标 `px`；100% 缩放时对应屏幕 CSS 像素。缩放或平移不改变实际间距。
4. 接受有限、非负的数值，步进为 1；`0` 表示边缘相接。空值、负数、非数字、非有限数不得触发排列，显示简短的输入错误。计算结果溢出时也不得提交。
5. 输入仅修改草稿。Enter 或「应用」执行一次排列；修改数值后直接点击「居中成列」也使用该有效草稿，不能仍用旧值。Escape 放弃草稿，失焦本身不重排，避免与点击产生两次历史。
6. 同一编辑器会话保留最近成功使用的间距，切换选区可继续使用。首期无需新增持久化偏好或修改存储结构；刷新后的元素位置照常保存恢复。
7. 少于两个可排列单元时不可执行。文字或 Markdown 正在编辑、对象正在拖动/缩放、富内容尺寸尚未稳定、只读模式时禁用动作。对画框、锁定内容等不支持的选择给出简短原因。
8. 输入框接管文字输入、删除、方向键、复制粘贴等按键；中文输入法组合期间 Enter 不提交，也不触发画布快捷键。
9. 完成后保留选区、工具、缩放和平移。它是一次位置整理，之后仍能自由拖动；不新增持续约束或内容变化后的自动重排。

## 排列单元与适用范围

- 普通形状、便签、图片和独立文字可作为单元。
- 容器及其绑定文字/Markdown 算一个单元，绑定文字不能重复计入数量或间距。容器与文字采用相同平移，保持原有内边距和文字布局。
- 按原生组合和组内编辑语义确定单元。完整组合整体移动，保留内部相对位置、组 ID 和嵌套关系；不能把组内多个元素拆成多个排列项。含锁定成员的单元不可移动。
- 以旋转后的轴对齐包围盒计算中心和间距；保留角度、尺寸及原有缩放。组的包围盒包含其完整内容。
- 箭头/线条不单独作为排列项；框选时顺带选中、且绑定到参与节点的连接线不计入卡片数量，但应保留选中状态并随绑定更新。组内线条随组整体处理。选择包含完全独立的线条/箭头时整体禁用并提示；不能静默略过用户明确选中的独立对象。
- 原生画框及其成员关系先不纳入此动作。选区包含画框，或排列单元位于画框内时，整体禁用并提示，避免移动后产生裁切或归属变化。
- 选区包含锁定排列单元时整体禁用，不静默略过节点或解除锁定。其他尚未支持的对象类型同样应给出原因。已删除元素始终不参与。
- 保证不同排列单元之间不重叠；保留组合内部布局，不整理其内部重叠，也不进行与未选对象的全局避让。

## 位置计算

所有几何计算均使用执行前同一份场景快照，单位是画布坐标。

1. 解析并校验排列单元，得到每项包围盒 `Bᵢ = [minXᵢ, minYᵢ, maxXᵢ, maxYᵢ]`。
2. 按原中心 Y 升序排列；相同 Y 按原中心 X，再按稳定元素 ID 打破平局。不要依赖框选手势顺序或选区对象键顺序。
3. 计算所有排列单元的联合包围盒中心 `(Cx, Cy)`。用于连接的独立箭头不扩大这个包围盒。
4. 设间距为 `g`、单元高度为 `hᵢ`、数量为 `n`，整列总高为 `H = Σhᵢ + g × (n - 1)`，起始顶部为 `T = Cy - H / 2`。
5. 每项平移量：`dxᵢ = Cx - (minXᵢ + maxXᵢ) / 2`，`dyᵢ = T - minYᵢ`；对整个单元应用相同 `dxᵢ/dyᵢ`，随后令 `T = T + hᵢ + g`。
6. 所有单元位置算好后，统一修正关联文字和连线，再一次提交完整场景。不要逐个更新原始场景，使后续计算读到已修改的中间值。

结果保持原选区整体中心；新列可以比原选区更高，向两端展开。不能为了维持原选区高度而压缩对象、缩小间距或允许重叠。

例如，三个对象的高度是 `80 / 120 / 60`，间距 `24`，原联合包围盒中心 Y 为 `250`。总高为 `308`，新顶部依次为 `96 / 200 / 344`，相邻边缘间距都为 `24`。宽度不同也都使用同一个 X 中心。

连续应用相同间距应得到相同位置；仅浮点误差内的变化视为无变化，不新增元素版本、保存任务或撤销记录。

## 实现建议

建议将几何计算与 UI 分开，保持改动集中：

| 位置 | 建议职责 |
| --- | --- |
| 新增 `src/selectionLayout.ts` | 单元解析、校验、稳定排序与位置计算；尽量保持纯函数 |
| 新增 `src/SelectionLayoutControls.tsx` / `.css` | 同名原生 action 的面板组件、间距草稿、校验和输入隔离 |
| `src/Whiteboard.tsx` | 在原生 API 就绪后注册动作，提供编辑状态和统一执行入口 |
| `src/richTextBridge.ts` / `scripts/excalidraw-rich-text.ts` | 仅在现有绑定桥不足时补齐绑定更新；避免扩大渲染适配范围 |

这些新增文件名是建议，尚未实现。DEV 可按实际复杂度合并。

优先通过 `api.registerAction` 注册 `name: 'alignHorizontallyCentered'` 的动作，提供一致的 `perform`、`predicate` 和 `PanelComponent`。按钮与间距「应用」共用同一计算和提交逻辑。`PanelComponent` 需保留原按钮在图标行中的位置，将间距输入放到独立整行；验证原生 flex 布局与面板滚动。

安装版同名注册按名称替换，并无公开的读取旧 action 或注销接口。注意以下接入细节：

- 原生 `excalidrawAPI` 回调发生在内部 `registerAll(actions)` 之前；在回调中同步覆盖会被原生注册覆盖。应在取得 API 后的 React effect 中注册，并随 API 实例变化重新注册。
- 注册不会主动刷新面板；验证首次加载、已存在选区、热更新时能显示自定义组件。组件类型保持稳定，状态通过稳定引用或订阅获取，不随每次输入/场景变化重建组件或反复注册，避免丢焦点和草稿。
- 自定义覆盖与编辑器实例同寿命，实例销毁时自然结束；清理自有监听即可，不虚构注销/恢复原动作接口。
- 面板 `updateData` 和 API 执行不保证先检查 `predicate`；`perform` 内也必须重新验证选区、编辑状态、间距和支持范围。
- 原生命令面板按 `actionManager.actions` 获取此动作，文案会对 `action.label` 调用翻译函数；保留有效的 `labels.centerHorizontally` 翻译键，将「居中成列」放在自定义 tooltip/aria-label。右键菜单等其他现有入口由 DEV 实测，统一触发新语义，不能声称本次已经验证。
- 优先让 `perform` 返回一次 `ActionResult`；不要同时 `updateScene` 再返回相同场景，造成双重提交。

如确实需要补充内部能力，沿用项目固定 `0.18.1` 的可复现构建适配，精确检查替换锚点，开发和生产均验证。不要直接修改 `node_modules`、使用 `as any` 虚构 API，或靠按钮中文文字和 DOM 点击拦截来替换动作。

## 绑定、历史和保存

- 修改元素必须保留 ID、图层顺序、组、图片文件、Markdown 源内容及原有 `customData`，通过原生元素更新方式正确推进版本；不原地污染既有历史快照。
- 所有节点目标位置确定后，统一修正绑定文字、箭头及箭头标签。验证未选中的绑定箭头、只有一端移动、两端同时移动、折线/肘形路由；绑定的 focus/gap 等语义保持正确。
- 原生绑定函数可能修改元素；若复用桥接，先复制所有受影响的对象再路由，避免撤销时原始位置已被修改。已有 `rebindRichContainers` 不等于自动覆盖本需求所有情况，必须实测。
- 一次居中成列及其全部连线变化只产生一个原生历史步骤，采用 `CaptureUpdateAction.IMMEDIATELY` 的一次 action 结果或等价单次提交。无效输入、禁用和无变化不产生历史；不能先提交普通居中再提交消除重叠。
- 沿用现有 `onChange`、IndexedDB 保存、原生 JSON 导入导出，不为排列另建文档模型或业务历史。不修改旧 `mindflow-flowchart-v1` 数据。
