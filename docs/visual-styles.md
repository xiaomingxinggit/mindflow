# 画布风格选项

2026-10-23。基于 `b6d2e32` 的新功能要求，执行聊天为 DEV。

## 用户已确认

- 默认采用现代商业风格，节点观感参考 Xmind 等成熟产品：规整轮廓、圆角、浅色填充、清晰线条与文字。
- 保留原有 Excalidraw 视觉，命名为“系统风格”。仅提供“现代风格”和“系统风格”两个选项。
- 字体使用操作系统默认无衬线字体，两个风格均不默认使用手绘字体。
- 切换风格时同时统一当前画布的全部元素，后续新建元素也沿用该风格。

## 交互与视觉

- 在白板紧凑工具区提供可发现的“画布风格”选择入口，可展示两种小预览；菜单或命令面板可复用同一动作。
- 现代风格：roughness=0、实心浅色节点、统一细描边、合适圆角、深色清晰文字、干净的中性色连线。新建文字字号可取适合桌面阅读的 18px 左右；已有字号与文字内容保留。
- 系统风格：恢复原生手绘线条和填充的视觉特征，文字仍采用系统默认字体。
- 样式作用于图形、独立/绑定文字、箭头/线和画笔；图片像素、裁剪和文件数据不受风格改变。便签保持可识别的暖色填充，同时采用系统字体和对应线条风格。
- 切换不改变文档文字、元素 ID、相对位置、形状种类、分组、图片、画笔轨迹、箭头路径和绑定。不为商业风格重建思维导图树结构。
- 更换字体后正确重测文字，绑定文字继续居中并保留多行内容。必要的文字排版调整可以影响文字框，不能无故重排整个画布。
- 一次风格切换作为一次原生历史操作，可整步撤销/重做。恢复画布风格后，选择项与新建默认样式应保持一致；不另建历史栈。

## 实现与保存

- 使用公开 `newElementWith` 更新元素样式/版本，一次 `updateScene` 以 `CaptureUpdateAction.IMMEDIATELY` 提交；同步 currentItem 的描边、填充、粗糙度、字体、圆角等默认值。
- 不把整幅画布交给 skeleton 转换器重建；它可能改变箭头、frame 和 ID。文字测量若需转换器，只临时测量相关文字/容器，再合回原元素。
- 字体要真正用于 canvas 测量/绘制、就地编辑、PNG 和 SVG，不能只改 HTML/CSS。安装版本内置 fontFamily=2 的字符串仅为 Helvetica，没有通用 sans-serif 回退，不能据此声称已采用系统字体。
- 可在一个小适配模块中，将公开 FONT_FAMILY 的 Helvetica 属性保留数值但设为不可枚举，并增加可枚举的 system-ui:2；锁定 0.18.1 的 getFontFamilyString 由此输出 system-ui。不得修改 node_modules；该兼容点必须有简短说明，初始化需幂等，并实际验证 SVG font-family。若找到更直接可靠的公共方式可替代。
- 原生 UI/欢迎提示也使用系统字体。保留用户手动选择其他属性的能力，不在每次 onChange 中强制重涂所有元素。
- 已保存场景没有风格偏好时按现代风格初始化；已有内容本次统一到现代风格。有偏好时恢复该选项；刷新、新建、原生文件导入后新绘制默认值一致。
- IndexedDB 保存风格偏好与必要 currentItem* 字段。原生导出会清理 currentItem*，需在小 preferences 对象显式保存；不保存整个 AppState。
- 如用元素 customData 标记风格协助原生撤销，合并保留其他 customData。图片只允许附加必要标记，不改图片本体。空画布无元素时仍能切换并保存默认风格。

## 验收与提交

在 `feat/visual-style-presets` 分支实现，保护外部未跟踪 AGENTS.md；按 code-documentation 项目约定同步 README 和实际验证记录。

验证只覆盖本次变更：一轮 build/lint；一个包含多行文字、矩形/菱形、标签箭头、便签、图片/画笔的桌面场景切换两种风格，确认内容/关系保留和撤销重做；新建元素、刷新恢复偏好；检查一个 PNG/SVG 的字体实际呈现与 SVG font-family。截图记录现代风格与系统风格供用户比较，不重测上一轮全套功能，不引入测试框架或压力测试。

检查差异后做本地 Git 提交，报告提交、验证结果及代表截图；不推送或创建 PR。
