# 画布风格选项

2026-10-23。基于 `b6d2e32` 的白板功能，在 `feat/visual-style-presets` 分支实现并完成本轮验证。

## 用户已确认

- 默认采用现代商业风格，节点观感参考 Xmind 等成熟产品：规整轮廓、圆角、浅色填充、清晰线条与文字。
- 保留原有 Excalidraw 视觉，命名为“系统风格”。仅提供“现代风格”和“系统风格”两个选项。
- 两种风格均默认采用操作系统无衬线字体。
- 切换风格时同时统一当前画布的全部元素，后续新建元素也沿用该风格。

## 已实现的交互与视觉

右上角紧凑工具区提供“画布风格”下拉选项，文件菜单和命令面板复用同一个切换动作。
风格、便签及素材库入口统一使用 12px 系统字体，控件高度为 36px；普通文字行高为 16px，
原生下拉选项的闭合值保留浏览器行高计算。
文件菜单的“命令面板”使用 16px `Command` 图标。

| 预设 | 节点 | 线条与文字 | 新建默认值 |
| --- | --- | --- | --- |
| 现代风格 | 规整圆角、浅紫色实心填充 | 无手绘抖动、紫灰细描边、深色文字、紫灰连线 | roughness=0、solid、系统字体、18px |
| 系统风格 | 原生手绘轮廓、浅蓝色斜线填充 | 手绘线条、深色文字 | roughness=1、hachure、系统字体、18px |

现代风格调色板为节点填充 `#F5F3FF`、节点描边 `#9B8BC0`、文字 `#343044`、连线 `#8B819F`。
便签保留暖黄色语义，随预设改变线条和填充方式。新便签为空白，首次编辑使用 16px 字号，
左上对齐且内边距为 16px；已有内容保留原字号。风格作用于图形、独立及绑定文字、箭头、线和画笔；图片只附加风格标记，像素、裁剪、尺寸及文件数据保持不变。

切换保留元素 ID、文字原文和原有字号、形状类型、非文字位置、分组、旋转、frame 归属、画笔轨迹及压力、箭头路径与绑定，不重排整个画布。字体变化会重新测量文字，绑定文字按原有对齐方式排版，必要时增加容器尺寸以容纳内容；中文多行保留。

有内容的场景每次切换作为一次原生历史操作，可整步撤销或重做，风格选择和后续绘制默认值同步恢复。空画布切换只改变默认偏好，没有文档元素变化，原生撤销不会恢复这次空画布切换；选择仍会保存并在刷新后恢复。

用户仍可用原生属性面板修改颜色、字体等属性，普通编辑及刷新不会被预设持续重涂。新建画布沿用当前风格和默认值。打开原生文件保留文件元素的视觉，带统一风格标记的场景可恢复对应选择；需要统一全部元素时显式切换预设。旧版 Mindflow 导入按当前预设生成元素。

矩形、菱形、椭圆、便签、文字、画笔各自保存描边与填充偏好；线条与箭头共享一组。
切换工具读取该工具的偏好，没有记录时使用对应风格默认色。修改某类已选元素的颜色也会
更新该类偏好，选择不同元素本身不会覆盖偏好。显式切换风格会清空各工具颜色记录并恢复
新风格默认值；刷新和普通工具切换保留记录。

## 实现与保存

- `src/visualStyles.ts` 的 `getStyleDefaults` 提供默认值，`applyVisualStyle` 使用公开 `newElementWith` 更新样式及版本。切换前给缺少当前标记的元素建立 `CaptureUpdateAction.NEVER` 基线，再用一次 `IMMEDIATELY` 提交最终变化，不另建历史栈。
- 文字测量仅在临时副本上执行：独立文字使用 `restoreElements` 刷新尺寸，绑定文字临时使用 skeleton 转换器测量，只将文字布局和必要容器尺寸合回原元素。不会用转换器重建整幅场景。固定文字框导入的 `autoResize=false` 字段保持不变，测量副本按容器重新计算标签布局。
- 元素标记保存在合并后的 `customData.mindflowStyle`，便签使用 `mindflowNote`；原有其他 `customData` 保留。`readSceneStyle` 忽略已删除元素，仅在有效标记一致时识别风格。`onChange` 仅在识别到风格变化时以 `NEVER` 恢复下拉选择和绘图默认值，不持续强制覆盖手动属性。
- `src/systemFont.ts` 针对锁定的 `@excalidraw/excalidraw@0.18.1` 提供幂等适配：保留 `FONT_FAMILY.Helvetica === 2`，将该属性设为不可枚举，增加可枚举的 `system-ui: 2`，让此版本的字体名称解析输出 `system-ui, Segoe UI Emoji`。适配在编辑器挂载前完成，不修改 `node_modules`。原生 UI 和欢迎提示也使用系统字体。升级依赖需重新核对这一兼容点。
- `src/whiteboardStorage.ts` 在现有 IndexedDB 场景记录的 `preferences` 中保存 `canvasStyle` 和必要的 `currentItem*` 字段，包括颜色、填充、线宽、粗糙度、透明度、字体、字号、对齐、箭头及圆角。原生序列化会清理这些绘图默认值，因此偏好单独显式保存，不序列化完整 `AppState`。
- `src/toolColors.ts` 的 `createToolColors` 观察原生工具与颜色变化；`preferences.toolColors` 在同一 IndexedDB 场景记录中保存各工具的 `{ stroke, background }`，不增加元素或业务历史。原生画布备份仍保存元素实际颜色，工具偏好属于本浏览器的工作区设置。
- 无风格偏好的已有本地场景首次恢复时统一为现代风格；已有偏好时保留场景及手动修改。场景、图片与素材库继续使用原有本地保存流程，旧 `mindflow-flowchart-v1` 值保持不变。

## 本轮实际验证

验证使用一个 1366×768 桌面浏览器场景，覆盖本次风格集成，没有引入测试框架或重跑上一轮全部编辑功能。

- 12 元素混合场景包含多行矩形、椭圆、菱形、带标签箭头、暖色便签、图片和画笔，现代与系统风格切换通过。逐字段确认 ID、类型、分组、角度、frame、原文、字号、容器绑定、箭头绑定和 points、画笔 pressures、图片 crop/fileId/scale/status 及其他 `customData` 保留；非文字位置及图片尺寸保持。
- 一次原生撤销 / 重做能恢复整场景风格，并同步选择项和 `currentItem*` 默认值；新绘制且没有预设标记的元素也验证通过，未引入 `flushSync`。固定文字框绑定标签在局部重测后保持原文、`autoResize` 和居中布局。
- 系统风格中新绘制矩形及刷新后维持 roughness=1、hachure、fontFamily=2；新建画布沿用系统风格。空画布改为现代风格并刷新后，选择、roughness=0 和 fontFamily=2 保持。手动红色修改、继续绘制及刷新后，元素颜色与默认颜色均保留。
- 项目打开入口导入原生文件后保留未标记元素原有 fontFamily=5，新绘制仍使用当前风格的 fontFamily=2 及对应 roughness；显式切换后全部文字统一到系统字体。原生 Ctrl+O 路径也实际导入通过，系统风格选择及 fontFamily=2、roughness=1、hachure 的绘图默认值保持一致。
- 就地编辑框实际计算字体为 `system-ui, Segoe UI Emoji`。现代风格 PNG 已真实下载并目视检查；SVG 的 9 个文字元素均输出同一系统字体族，20 / 22 / 24px 原字号保留。
- 最终 `npm run build`、`npm run lint` 和 `git diff --check` 通过。构建保留上游大包的 chunk 大小提示，本轮未调整分块策略。
