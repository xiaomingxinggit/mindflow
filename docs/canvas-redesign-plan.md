## 界面与操作原则

- 使用 Excalidraw 原生顶部工具条、按需属性栏、左上文件菜单、左下视图与历史、右侧素材库，整体布局贴近参考站。
- 中文界面，默认空白浅色画布；保留深色主题。全屏容器有明确高度，属性面板和菜单不被旧 CSS 覆盖。
- 应用壳只添加 Mindflow 名称、文档名、保存状态、便签和必要的旧文件导入；避免用大标题、冗余侧栏挤占画布。
- 稳定包虽导出 `MainMenu.DefaultItems.CommandPalette`，实际编辑器没有挂载可用面板。移除这个无效入口，以轻量 `CommandPalette` 承接 Ctrl / Cmd + / 和菜单命令搜索，不复刻编辑器内部操作系统。原生文字搜索继续使用 Ctrl / Cmd + F。
- 双击空白创建原生文字，双击形状编辑绑定文字，遵循原生编辑器行为。中文输入法、Enter 换行和编辑时快捷键由原生编辑器处理，不叠加上一版键盘监听。
- 便签可放在紧凑扩展入口，创建为原生可编辑元素，能和其他图形一样移动、复制、分组、保存。若稳定包有原生能力则直接复用，不维护额外便签数据模型。
- 保留必要开源归属；不复制账号推广或未接通的服务按钮。

## 旧数据与文件兼容

1. 原 `mindflow-flowchart-v1` localStorage 值保持不变；新白板不写回旧格式。
2. 无新白板记录且存在旧画布时，在打开时完成一次转换。旧 JSON 文件也通过同一个转换入口进入新画布。
3. 旧节点映射为原生矩形/菱形/圆角矩形，保留文字、位置、主要颜色；按旧 UI 尺寸和多行内容估计宽高。旧连线转成带形状绑定的原生箭头，保留端点与文字。
4. 使用 `convertToExcalidrawElements` 和官方恢复 API，保留节点 ID 或建立明确映射，确保形状移动后箭头仍跟随。旧折线/曲线可按原生路径近似恢复；不做复杂像素级迁移。
5. 先检查文件/旧文档的必要结构，再替换当前场景；无效导入显示错误，当前内容不受影响。不恢复旧思维导图/系统架构格式。

## 保存与资源

- 新白板使用 IndexedDB 的简单单场景记录，包含有效元素、图片 files、名称及少量视图偏好；素材库单独记录即可。可用一个轻量依赖或短小原生封装，不建立通用仓储框架。
- 保存经官方 `serializeAsJSON(elements, appState, files, 'local')` 的场景，并显式补充名称、theme、scrollX/scrollY、zoom 等必要偏好。不能用会丢图片的 `'database'` 参数；不能序列化整份带 Map/Set/文件句柄的 AppState。
- onChange 的业务保存适度防抖；启动恢复完成后再允许覆盖存储。写入顺序保持最新，页面隐藏或离开尽量刷新待保存内容。显示“保存中 / 已保存 / 保存失败”，失败时原生导出仍能使用。
- 主题、素材库与图片都要在刷新后恢复；不将图片 base64 放进小容量 localStorage。
- 按官方方式在编辑器加载前设置 `EXCALIDRAW_ASSET_PATH`。字体从已安装包复制到本地静态资源，开发/构建命令自动准备资源；避免依赖外部字体 CDN。
- 如资源是构建时生成，加入 gitignore 并由可复现的脚本复制，不把 node_modules 或大批生成产物提交。

## 清理与代码组织

- App 改为原生编辑器容器，移除 ReactFlowProvider、React Flow CSS、旧的 FlowchartBoard/ThoughtNode/配色上下文/自制历史及全局快捷键代码。
- 旧 flowchart 模型仅保留迁移和旧 JSON 读取需要的部分，去掉对 `@xyflow/react` 的类型依赖；移除已无用途的 React Flow 依赖及相关样式。
- 建议小范围拆分：白板组件、场景/素材库保存、旧数据转换，以及资源准备脚本。以实际复杂度决定，不引入额外应用框架、插件框架或服务层。
- 原生 API 以安装版本类型为准，在线文档可能领先 stable；不要使用 `as any` 绕过不存在的功能，也不要强制安装冲突依赖或擅自降级 React。
- 同步 README 的技术栈、工具、快捷键、保存/备份方式和已验证事实，使用项目指定的 code-documentation skill。AGENTS.md 是外部新增且未跟踪文件；保护其内容，必要时最小同步相关技术/路径描述，不将外部内容顺带提交。

## 验证与提交

基于 `ef95b08` 和本次方案提交，在 `feat/excalidraw-core` 分支实现。所有代码、文档与依赖变更检查后做本地提交；不主动推送或创建 PR。

验证保持适量，优先一次主流程按类别检查自有集成，不逐项重测官方编辑器：

1. 最终 `npm run build` 和 `npm run lint`；修复代码后只重跑相关失败检查。
2. 桌面浏览器连贯流程：画一个形状并写中文多行 → 再建形状并用带标签箭头绑定 → 移动后连线跟随 → 多选复制/组合 → 变换/样式/撤销重做 → 画笔/橡皮 → 添加图片和便签 → 刷新恢复。
3. 顺带验证一个素材库项目的添加/插入/刷新、一份原生文件保存/打开、PNG/SVG 实际导出，以及一份旧版画布的节点/文字/连线转换与一个无效文件错误。
4. 确认主题和视图刷新恢复，本地字体请求可用；检查 1280×800 和 1366×768 布局，保存一张代表性截图。旧 hash 仍只打开当前编辑器。
5. 不引入大规模测试框架，不跑浏览器矩阵和压力测试，不专门重测原生每一种样式组合。新发现的实际问题修复并验证后停止重复测试。

最终交付：实现摘要、实际已通过的验证、分支与 commit、界面截图和可试用的本地地址；明确剩余限制。

## 实施与验收记录

以下为 2026-10-23 实际实现与已运行的验证记录。

### 已实现结构

- `App.tsx` 仅挂载单一 `Whiteboard`。删除旧 FlowchartBoard、ThoughtNode、配色上下文、自制历史与 `@xyflow/react`；绘制、选择、变换、样式、连接和历史使用原生核心。
- `Whiteboard.tsx` 保留原生中文工具条、属性、文件菜单、素材库和帮助；增加名称、保存状态、便签、旧 JSON 导入及命令面板。原生命令面板空入口已替换为实际可操作的本地命令列表，提供工具、文件下载 / 打开、导出、主题和视图命令。
- 便签使用原生 rectangle 和绑定文字，不额外预分组；双击编辑，拖动后文字随形状移动，需要时按普通图形组合。
- `whiteboardStorage.ts` 使用 `mindflow-whiteboard-v1` IndexedDB 数据库，`workspace` store 内的 `scene` / `library` 两条记录；场景按 500ms 防抖，顺序写入。场景使用 `serializeAsJSON(..., 'local')` 包含图片，另存名称、主题、缩放平移、网格、吸附和简洁模式偏好。恢复完成后才启用保存，失败显示提示。
- `legacyFlowchart.ts` 和精简后的 `flowchart.ts` 只负责旧流程图校验与转换；节点保留 ID，文字使用绑定文本，箭头用 `start` / `end` 绑定原节点。旧 `mindflow-flowchart-v1` 不改写。
- `scripts/prepare-excalidraw-assets.mjs` 在 `predev` / `prebuild` 复制包内字体到 `public/excalidraw/fonts/`，资源目录被 Git 忽略。`index.html` 在模块加载前设置 `EXCALIDRAW_ASSET_PATH`，生产与开发均使用本地资源。
- 保留 React 19，lockfile 实际 React / ReactDOM 为 19.3.0。安装时旧 `@radix-ui/react-tabs@1.0.2` 子树有上游 peer 声明告警；未降 React、未使用 force 或额外覆盖依赖。
