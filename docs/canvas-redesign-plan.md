# Mindflow 无限思维画布改造方案

日期：2026-10-23。开发负责人：现有聊天 DEV（01a16858-7e99-7653-a8cb-63b51297a1f1）。

## 1. 目标与第一版边界

用户已确认：个人在电脑上使用；边想边记，让零散念头逐渐连成结构；在任意空白处创建内容，再拖动和连线。

将现有三个模式收敛成一个自由思维画布。完整移除旧思维导图、系统架构及相关逻辑，在现有流程图基础上重做体验。

第一版采用以下可调整的产品假设：单张当前文档、多行纯文本想法、自由有向连线与可选连线文字、本地自动保存、JSON 导入导出。节点可以独立存在、互相连接并形成回路，不要求中心主题或父子树。先不扩展图片、富文本、分组容器、多文档管理、AI、协作、云同步和演示。

## 2. 参考与布局

已查看 https://excalidraw.com/ 实际桌面页面。借鉴画布占满窗口、顶部居中悬浮工具条、左上文件菜单、左下视图/历史控制、选中元素后按需出现属性面板的组织方式。使用自己的中文界面和清晰节点样式，无须复制手绘渲染或引入 Excalidraw 引擎。

```text
┌ 文件菜单 · 文档名/保存状态 ── [选择 平移 想法 判断 起止] ─────┐
│ [选中时的属性浮层]                                      │
│                                                       │
│                  整屏自由画布                          │
│              想法 ── 关系说明 ──→ 想法                 │
│                                                       │
└ [缩放 适应] [撤销 重做] ─── 轻量操作提示 ─── [帮助] ─────┘
```

- 默认浅色背景、低对比点阵、紧凑白色浮层、单一强调色；选中态、悬停态和连接点清楚。
- 移除固定大标题栏、常驻图形库、常驻属性栏和整条底部状态栏，让画布成为主体。
- 左上紧凑文档区可改名、查看保存状态；文件菜单包含新建、导入 JSON、导出 JSON、网格开关。
- 顶部工具条仅保留实际实现的工具：选择、平移、默认矩形想法、菱形判断和起止图形。选择图形工具后点击画布放置一次，随即回到选择并直接输入。
- 左侧浮动属性面板仅在选中时出现，提供形状、颜色、连线文字和线型；多选时只显示批量复制/删除等适用操作。取消选择后收起。
- 左下缩放/适应与撤销/重做；右下简短帮助。入口不承载旧模式切换。
- 首次进入或新建是空白画布，中心仅显示“双击空白处，记下第一个想法”等轻提示；创建后消失。
- 以 1366×768 与 1280×800 的电脑窗口为布局依据，浮层不可互相覆盖或挡住主要操作；小窗口允许压缩次要文字。

## 3. 核心交互与验收行为

1. 双击画布空白处，在鼠标对应的画布坐标创建一个默认矩形想法，立即进入节点内编辑。禁止双击缩放与创建动作冲突；缩放/平移后位置仍准确。
2. 双击已有节点直接修改多行文字，取消现有 40 字 UI 限制。支持中文输入法；Enter 换行，Ctrl/Cmd+Enter 或失焦完成编辑；Escape 结束编辑并回到画布。输入中的 Delete、空格、V/H 等按键不得触发画布快捷操作。节点随文字合理增高，长文字换行。
3. 拖动节点自由摆放，从节点连接点拖到其他节点建立箭头；可给连线添加说明并切换折线/曲线/直线。循环和跨节点关系允许；沿用现有阻止连接自身的简单规则。
4. 点击选择、拖拽框选、批量删除、Ctrl/Cmd+D 复制节点及所选节点间连线。删除节点同时删除相连边。
5. V 选择、H 平移，按住 Space 临时平移；滚轮缩放、适应全部；网格可关闭且默认不强制吸附，以方便随手记录。
6. Ctrl/Cmd+Z 撤销，Ctrl/Cmd+Shift+Z 或 Ctrl/Cmd+Y 重做。一次拖动、一次连续文字编辑、一次删除分别作为完整一步；选择、测量和缩放不产生文档历史。
7. 内容自动保存，刷新后节点、文字、位置、连线保持。保存失败需有可见提示并允许导出；新建与导入可撤销。

## 4. 删除与保留的准确边界

### 必须移除

- 重写 `src/App.tsx` 为单画布入口；删除 `MindFlow`、`TopicNode`、旧动画边、三模式状态和 hashchange 路由。
- 删除 `src/mindmap.ts`、`src/useDocumentHistory.ts`、`src/ArchitectureBoard.tsx`、`src/ArchitectureBoard.css`、`src/architecture.ts`。
- 移除 `src/App.css` 及其引用；新画布需要的样式统一放在当前画布样式里，尤其不要遗留全局隐藏/禁用连接点的规则。
- 删除 `FlowchartBoard` 中两种旧模式的链接、无用图标、文案、导入和调用，以及树结构、自动树布局、固定 AI 视频架构、演示/动画的业务逻辑。
- 更新 `README.md`、`index.html` 的旧功能描述、页面标题和使用说明；清理旧模式专用检查脚本，不复用其演示/动画测试。
- 旧 `#mindmap` / `#architecture` URL 只打开当前画布，不存在隐藏模式或兼容页面。无需引入路由框架。

### 直接演进

- 保留 React + TypeScript + Vite + React Flow + lucide-react 技术栈。
- 以 `src/FlowchartBoard.tsx`、`src/FlowchartBoard.css`、`src/flowchart.ts`、`src/useFlowchartHistory.ts` 为实现基础；模块按职责整理，避免大范围无意义重命名。
- 保留已有节点/独立连线模型、坐标转换、连接点、历史、复制、文件导入导出与本地保存能力。
- 第一版可继续沿用 `start/process/decision/end` 内部类型及 `mindflow-flowchart-v1` 存储，默认 process 节点文案改为“新的想法”。界面用形状/想法语言，减少格式变更和迁移成本；已有流程图正常读取，新用户使用空白文档。
- 删除旧思维导图的读写和转换逻辑即可；不遍历或清空浏览器里的废弃存储键，不实现旧树形导图迁移。
- 保留外部 JSON 导入的必要结构校验、文件读取错误和浏览器保存失败处理。内部遵循 TypeScript 明确约束，不新增通用验证框架、多层 fallback、重复 try/catch、任意限制或没有用途的兼容层。

## 5. 代码组织建议

`App` 仅负责 ReactFlowProvider、官方基础 CSS 与单画布入口；`FlowchartBoard` 负责画布与浮层；自定义节点承担就地编辑；`flowchart.ts` 负责文档类型/文件边界；现有 history hook 负责历史。若就地编辑使主文件明显拥挤，可提取一个节点组件，不预先搭建插件系统、全局状态框架或服务层。

React Flow 的拖拽/选中状态与业务文档历史继续区分；编辑中的输入焦点/草稿保持局部状态，不序列化回调、DOM、测量数据和临时选中态。

## 7. 适量验证与完成标准

- 完成实现后运行一次 `npm run build` 和一次 `npm run lint`；修复相关失败后重跑对应检查。
- 一条桌面浏览器主流程：空白打开 → 双击创建 → 中文多行输入 → 再建节点 → 拖动/连线并加文字 → 删除/撤销/重做 → 刷新恢复 → JSON 导出/导入。确认连续编辑和拖动的撤销粒度，以及编辑时快捷键隔离。
- 顺带在缩放/平移后创建一次节点，检查工具放置一次即返回选择；既有流程图能读取。
- 一次界面检查覆盖空白、选中两种状态和两种桌面尺寸；检查旧 hash 不再进入旧模式。保存代表性的截图供用户查看，临时产物不提交。
- 一个无效 JSON 导入检查即可确认可见错误且当前文档未受损；不铺设畸形输入矩阵或专门模拟各种存储故障。
- 使用源码搜索确认旧模块 import、旧页面入口和运行逻辑已删除。需求说明和历史记录里提及旧模式不算残留。
- 当前没有单元测试框架；优先复用现有浏览器工具，不引入大规模测试设施、不做全浏览器矩阵和无目标压力测试。通过后停止重复测试。
